# 拜访速记：客户提问 + 日报总结

每次拜访给销售两样东西：

1. **客户提问**：客户在这次拜访里问的所有问题，**一字不改**地从逐字稿里抄出来。
2. **日报总结**：100 字以内，围绕这次拜访的目的来写，销售可以直接贴进日报。

本技能只读妙记，不写销售易、不写多维表格、不发消息给别人。

## 1. 读逐字稿

- 用户给了妙记链接：`minute_token` 是链接里 `/minutes/` 后面那段。用户说「刚才/今天的拜访」：找当前用户今天的妙记，多条就逐条出速记。
- 读法（任选可用的）：「飞书妙记」连接器；或 `lark-cli minutes +detail --minute-tokens <tok> --transcript --summary --as user`，逐字稿写在 `./minutes/<tok>/transcript.txt`。
- 妙记没有读权限时，按 `visit-to-xsy` 第 1 节的办法去「录音信息整理」表找这条录音的逐字稿文档。都读不到就告诉用户读不到，**不要用 AI 总结代替逐字稿去摘提问**。
- 内部会议、培训、闲聊、设备测试等不是客户拜访的：告诉用户「这条不是客户拜访，没出速记」。
- **读全文。** 录音很长（一小时以上）时分几次读，每次从上次读到的那段接着读，一直读到最后一段。读完再定目的和总结，会末的约定常在最后。
- 没读全（分页没读完、文件截断），或者读到的逐字稿是空的、格式看不懂：告诉用户哪一段没读到。这种情况**不能写「这次客户没有提问」**。
- 妙记逐字稿是一段段的：`Speaker 2 00:01:42.600` 一行，下面是这段话的原文。录音信息整理表里的逐字稿文档格式可能不一样（例如时间、说话人和原文在同一行），一样以每段的时间和原文为准。
- **说话人标签不可靠**：同一个人可能被标成两个编号，一段里也可能混着双方的话。逐句判断是谁说的：看称呼（「张总」「小谭」）、问的是谁家的东西、接下来是谁在回答。我方所有人（销售、协访同事）算「我方」，客户那边所有人算「客户」。

## 2. 客户提问：逐字抄

### 抄哪些

客户方的人在拜访中提的问题**全部**抄出来，按出现顺序排。判断标准是：这句话是不是在向别人要信息或要确认。后面有没有人回答可以作旁证，没人回答的也收。

- 带问号或「吗、呢、怎么、多少、能不能、是不是、有没有、几」等的疑问句。
- 意思是在问、但写成陈述句的，例如「你给我讲讲你们这个怎么收费」「我想了解一下你们的交付周期」。
- 带着质疑或确认的追问，例如「两周就够了？」「尾款是验收后付，对吧？」。
- 客户问自己同事的业务问题（「老周，我们这个系统谁在维护来着？」）也收，在列表后标出来（见第 5 节）。
- 同一个问题在不同时候问了两次，两次都抄。

不抄：

- 我方（销售、协访同事）问的问题。
- 寒暄客套（「最近忙吗」）、没听清的反问（「啊？」「你说什么？」），以及说完不等回答、自己接着往下讲的口头语（「对吧」「是吧」）。
- 要求、表态、安排，没有在问（「这个你们再考虑一下」「那你们先拿数据测一下吧」）。
- 话说了一半、自己收回去的（「还有就是价格……算了，等上完会再说」）。

### 怎么抄（最重要）

- **逐字复制逐字稿原文。** 不改错别字（转写错了也照抄，例如「私有话部署」「销售一」），不补字、不删字、不改标点、不删口头语，数字和空格也照原样（原文是「 30 万」就抄「 30 万」，不要改成「30万」）。原来什么样，抄出来就是什么样。
- **以整句为单位**：从这句话的开头抄到这句话的结尾。句子的边界是原文的句末标点（。？！；），逗号不算边界。一句里问了两件事，整句一条，不拆。
- 前半句交代背景、后半句才是问题的，整句抄，不要只抄后半句。例如要抄「我们现在工单系统是自己开发的，你们这个能对接吗，接口是你们来写还是我们来写？」，不能只抄「你们这个能对接吗……」。
- 连续几句都在问同一件事，可以连着抄成一条，中间不能跳过任何字。问句后面紧跟的解释或补充（不是在问）不抄，那是日报总结的素材。别人的回答更不能带进来，哪怕和问题在同一段里（例如「测一轮要多长时间？大概一周。」只抄问句）。
- 每个问题只抄一次：已经合在一条里的，不要再单列；不相干的两个问题不要写成一条。
- 一个问题被我方插话（「嗯」「对」）切成两段时，同一个序号下分两行，每行写那一段自己的时间和原文。前一段照原样抄到那段结尾，哪怕停在逗号上；后一段从那段开头抄。**不要用「……」或别的符号把两段拼成一行。**
- 每行前面写这段话的时间，取逐字稿段头的「时:分:秒」，例如 `00:01:42`；时间和原话之间只隔一个空格。只有逐字稿那段本身没有时间的，才写 `--:--:--`。

### 抄完自查

逐条确认每一行都能在逐字稿里**原样**找到，而且是从句子开头抄到句子结尾。能跑命令时用 `grep -F` 查：

```bash
grep -cF -- '那私有话部署的话，对服务器有什么要求，要几张卡？' minutes/<tok>/transcript.txt   # 结果是 0 就是抄错了
```

查不到的那条重新从原文复制，不要凭记忆改。

## 3. 拜访目的

从下面选一个，按这个顺序定：
1. 用户在对话里明说的目的。
2. 销售开场明说的目的（「今天主要是……」）。中途话题跑开了（比如被叫去临时演示），仍按开场的目的。只有中途**明确换了这次拜访的目标**（客户说「今天先谈合同」，双方随后就谈合同），才按换了之后的，并在依据里写出变化。
3. 都没明说时，看实质谈了什么、最后约定了什么，妙记标题作旁证。
4. 依据不够就写「目的待确认」，日报照样写。

| 目的 | 典型内容 |
|---|---|
| 需求调研 | 了解客户现状、问题、需求和预算，多是初次或早期拜访 |
| 产品介绍 | 介绍或演示我方产品 |
| 方案交流 | 汇报方案，或者和客户技术人员做技术交流 |
| 项目推进 | 推进内部流程、决策链、时间表，确认下一步 |
| 商务谈判 | 报价、折扣、付款方式、合同条款 |
| 交付回访 | 实施、验收、售后使用情况 |

都不像就写「其他：<几个字说明>」。

## 4. 日报总结（100 字以内）

围绕拜访目的写，**只写录音里真实出现的信息**，不编数字、时间和人名，不评价客户和销售。

| 目的 | 写什么 |
|---|---|
| 需求调研 | 客户现状和痛点、核心需求（上线时间、预算等），下一步 |
| 产品介绍 | 介绍了哪些产品或功能，客户最关注什么、怎么反馈，下一步 |
| 方案交流 | 交流了什么方案或技术点，客户的反馈（认可或疑虑），下一步 |
| 项目推进 | 推进到哪一步，决策流程和关键人的态度，卡点或风险，下一步 |
| 商务谈判 | 报价和预算、客户提的条件、双方的分歧和让步，下一步 |
| 交付回访 | 使用或实施情况、出现的问题、怎么处理，下一步 |

- 开头写客户名称（逐字稿、妙记标题里有就写，没有就不写），然后直接写内容，不写「本次拜访」「经沟通」这类套话。
- 客户方的人只写录音里出现过的称呼（「张总」「李工」），对不上是谁说的就不写名字。
- 先写和目的直接相关的进展或障碍，再写约定的下一步。下一步有时间、负责人就写上，例如「周四前发调整后的报价」。
- **保留原话的确定程度。**「基本通过」「原则上可以」「要回去申请」「希望三月前上线」不能写成「已通过」「已同意」「已批」「三月上线」。录音里没有结论或约定的，不补。
- 一段话，不分条，不用 Markdown。
- **100 字以内，标点、数字、字母都算字数。** 能跑命令时数一下：`python3 -c 'import sys; print(len(sys.argv[1]))' '<总结>'`。超了先删次要细节，下一步最后删。
- 总结是概括，可以用自己的话；客户提问那一节才要求逐字。

## 5. 输出

固定按这个格式回给用户（方便直接复制，也方便核对）：

```
拜访速记｜<客户名称> · <录音日期 MM-DD HH:mm>

拜访目的：<目的>（<一句依据，例如销售开场的原话>）

日报总结（<字数> 字）：
<总结>

客户提问（<条数> 条，逐字原话）：
1. <时:分:秒> <原话>
2. <时:分:秒> <被插话切开的前一段原话>
   <时:分:秒> <后一段原话>
问的是客户自己同事：第 X 条
拿不准是谁问的：第 Y 条
```

- 标题里的客户名称：逐字稿或妙记标题里有就写；没有就写妙记标题；连标题都没有就只写录音日期。不要写「未提及」之类的说明。
- 拜访目的后面的括号里要写依据，不能空着。
- 客户一个问题都没问：「客户提问」那节写成 `客户提问：这次客户没有提问。`，下面不再列任何条目。
- `问的是客户自己同事`、`拿不准是谁问的` 两行，没有就不写，有多条用顿号隔开（`第 3、8 条`）。
- 拿不准是谁问的：例如一段里突然冒出一句问话又马上被回答，说是销售自问自答、说是客户插问都讲得通。这种照样抄进列表并标出来，不要为了干净把它删掉。
- 不加别的段落。用户要别的内容（完整纪要、录进销售易等），交给对应的技能。
