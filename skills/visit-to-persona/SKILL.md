# 拜访 → 销售画像工作台

`visit-to-xsy` 管的是把一次拜访录进销售易。本技能在它后面：把**已写入**的拜访整理成工作台要的格式送进去。画像分数、维度归纳、派单推荐都由工作台按固定规则算，**本技能不打分，不写评语，不评价任何人**。

所需能力：
- `lark-cli`（user 身份）：读台账、妙记、云文档。
- 「销售易 CRM」连接器：**只读**，用 `entity-detail`、`entity-search`、`user-detail`、`opportunity-stageInfo`、`metadata-entityDescribe`。
- 「销售画像工作台」MCP：工具 `persona_ingested`（查已写过的）和 `persona_ingest`（写入）。连接方法见仓库 `workbench/README.md`。**入参以工具声明的 schema 为准**，下文说的字段名和它不一致时按工具的来。

台账位置：Base `{{recording_base.base_token}}`（「录音的汇总统计」），表 `{{recording_base.ledger_table_id}}`（「拜访跟进台账」）。
（`{{recording_base.…}}` 由部署脚本从 `config/app.json` 的 `recording_base` 段填入。如果看到的还是 `{{…}}` 原样，就去 `config/app.json` 里取对应的值。）

## 1. 找出要送的拜访

1. 调 `persona_ingested`，拿到已经写过的拜访编号，以及结果还是「在跟」的商机编号。
2. 读台账，只取 `处理状态=已写入` 的记录：
   ```bash
   lark-cli base +record-list --base-token {{recording_base.base_token}} --table-id {{recording_base.ledger_table_id}} \
     --as user --json --limit 200 \
     --field-id 处理状态 --field-id 客户名称 --field-id 商机 --field-id 拜访目的 --field-id 拜访时间 \
     --field-id 妙记链接 --field-id "商机情报（MEDDPICC）" --field-id 销售易跟进记录ID
   ```
   超过 200 条用 `--offset` 翻页。台账读不了（`91403` 等）就停下，告诉用户当前账号没有这张表的读权限，要找表的负责人开通。
3. 逐条决定：
   - 记录编号已在 `persona_ingested` 里：跳过，记为「已写过」。
   - `商机情报（MEDDPICC）` 里 `opportunityId` 为空（这次拜访只挂了客户）：跳过，记为「没有商机」。工作台的每次拜访都要挂在商机上。
   - `商机情报（MEDDPICC）` 为空（台账加这个字段之前的老记录）：可以补，见第 3 步的「老记录」。
   - 用户说了时间范围（如「最近 30 天」「这周」）就按 `拜访时间` 过滤；没说就全部处理。

## 2. 读逐字稿，切成发言

- 妙记链接里 `/minutes/` 后面那段是 `minute_token`：`lark-cli minutes +detail --minute-tokens <tok> --transcript --as user`（逐字稿存成文件，默认在 `./minutes/<tok>/`，读那个文件）。
- 读不到（没权限）时，按 `visit-to-xsy` 的做法走录音信息整理表：Base `{{recording_base.base_token}}`、表 `{{recording_base.recording_table_id}}`，按录音时间对上这条录音，用 `lark-cli docs +fetch --doc <录音逐字稿链接> --doc-format im-markdown` 读。两条路都读不到就跳过，记为「读不到逐字稿」。
- 按语义判断每句是谁说的。逐字稿的说话人标签可能不准。**我方所有人（销售、协访同事）都记为「销售」，客户方所有人都记为「客户」。**
- 每段连续发言是一条 `turn`：`{role, text}`。`text` 是逐字稿**原文**，不改写、不总结、不补标点、不删口头语。同一人连续说的几句可以合成一条。
- 寒暄、设备调试、和客户无关的内部对话可以去掉，但不能改动留下的原文。

## 3. MEDDPICC 八项

- **正常情况**：直接用台账 `商机情报（MEDDPICC）` 里的 `fields`。这是销售确认过的版本，**不要重新提取，也不要改内容**。
- 逐项核对：`known=true` 的项，`quote` 必须是某一条「客户」发言 `text` 的原样片段。
  - 对不上多半是切发言时把这句话切开了：调整切分，让这句话落在一条客户发言里。
  - 调整后仍对不上（例如销售确认时改过原话）：这一项改成 `{"known":false,"summary":"","quote":""}` 再送，并记入汇报的「引文对不上」。**不要为了对上而改原话或改逐字稿。**
- **老记录**（台账没有这个字段）：按 `visit-to-xsy` 第 4b 节的规则从逐字稿提取八项。每一项都必须能逐字引用客户原话，引不到就记为未知。这些拜访在汇报里单列为「补提取（销售未确认）」。

八个键：`pain` 痛点、`metrics` 量化收益、`economic_buyer` 经济决策人、`decision_criteria` 决策标准、`decision_process` 决策流程、`paper_process` 采购/合同流程、`champion` 内部支持者、`competition` 竞争。

## 4. 五种对话标注

在发言上加 `signal`。**只在有把握时标，拿不准就不标**；不标只会让这一项没有依据，标错会让画像失真。每条发言最多一个标注，不为了凑标注去挪动或改写发言。

| 标注 | 标在谁身上 | 什么时候标 |
|---|---|---|
| `next` | 客户 | 客户明确认下一个具体的下一步：谁、什么时候、做什么。例：「好，下周三我带 IT 一起来看演示。」只是销售提议、客户没表态的不算。 |
| `comparison` | 销售 | **紧跟**在客户说出替代方案（就是 `competition` 那句原话）**之后的下一条**销售发言，提出了双方都能复核的比较办法。例：「我们用您上个月的同一批数据，两家各跑一遍，对一下准确率。」泛泛地说「我们比他们好」不算。中间隔了别的发言就不标。 |
| `technical_question` | 客户 | 客户提出一个具体的技术问题。例：「断网的时候扫码数据会丢吗？」 |
| `technical_answer` | 销售 | **紧跟**在那条技术问题之后的销售发言，给出了具体解法（怎么做到的），不是「没问题」「可以的」。 |
| `validated` | 客户 | **紧跟**在那条解法之后的客户发言，说明客户自己试过或核对过。例：「刚才拔网线试了，数据都在。」 |

技术问答只标**一组**「问题 → 解法 → 实测」：选最完整的那组，其他技术问题不标。

## 5. 商机和销售（只读销售易）

对每个要送的商机，用 `opportunityId` 读销售易：
- `entity-detail` entity=`opportunity`：商机名称、所属客户、金额、负责人、状态（`1` 进行中 → `在跟`，`2` → `赢单`，`3` → `输单`）、赢单/输单的结案日期。
- `opportunity-stageInfo`：当前阶段名称。
- 客户的行业、规模：`entity-detail` entity=`account`。字段的 apiKey 各租户不一样，先用 `metadata-entityDescribe` 找到再读，**找不到就留空，不要猜**。
- 竞争对手：`entity-search` entity=`opportunityCompetitor`，按 `opportunityId` 查，名称用顿号连起来。没有就留空。
- 金额换算成**万元**。没有金额就留空。
- 负责人：`user-detail` 取姓名。销售编号用销售易用户 ID，商机编号用销售易商机 ID。

`persona_ingested` 列出的「在跟」商机也要重读一遍，状态变了（赢单/输单）就跟这次的数据一起送，工作台的赢单率和派单依据靠它。

## 6. 写进工作台

- 拜访编号用**台账记录编号**（`rec…`），标题用「客户名称 · 拜访目的」，日期用 `拜访时间` 的日期（`YYYY-MM-DD`）。
- 每次 `persona_ingest` 最多送 10 次拜访，连同它们用到的商机和销售一起送。
- 看返回：
  - 被拒的拜访，如果原因是这边的切分或标注（引文落不进客户发言、标注位置不对），按第 2–4 步改了再送**一次**。
  - 其他原因（缺商机、数据本身对不上）不重试，记进汇报。

## 7. 汇报

几句话就够：
- 新写入几次拜访，其中补提取（销售未确认）几次；更新了几个商机的输赢。
- 跳过了多少，按原因分：已写过、没有商机、读不到逐字稿、校验没过（列出拜访和工作台给的原因）、引文对不上的项。
- 不复述画像分数，不评价哪位销售。想看结果请打开工作台。

## 不做的事

- 不写销售易，不改台账，不改逐字稿和销售确认过的内容。
- 不在本技能里打分、排序或给人下结论。
- 读不到的数据留空，不编造。
